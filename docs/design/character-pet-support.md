# 人物辅助与宝宝技能、条目

## 需求与契约

自由目录按施法主体开放。正式首测有 61 个技能原型、62 个机制效果，人物可学 40 项，宝宝可学 34 项，13 项共享。职业旧行仍供原有角色及其技能重数使用。人物与宝宝各自拥有技能，宝宝的 20 个条目点单独持久化。切换主体或重登后，客户端从应答中的宝宝实例号辨别目录。人物辅助面板与战斗对齐施放方的治疗、独立护盾、分类耗蓝，宝宝不读取主人装备。

## 状态与数值

场景在线程内从会话角色查找宝宝实例。种类种子和旧已学 ID 在缺少显式等级时视为一重。正重须再通过实际表行、施法主体和当前等级上限，其他持久值继续随实例携带。角色和宝宝使用同一升级计价和次数规则，不同主体分别提交自己的候选状态。宝宝修习先计算派生量与当前血蓝，再将候选宠物、钱包在同一次场景操作和玩家存档中提交，成功后推送宝宝列表。战斗快照把可施放主动写入列表，主动、被动、追击与开场的合法有效重数写入映射。

人物来源使用穿戴实例、固定词条选择、法宝表及生效被动。装备加成按通道和参数汇总后依全身上限截取，同类按物品号和词条号稳定分摊有效贡献。条件法宝独立列出。治疗、护盾和耗蓝修正各自选取同类最强正负项，面板、技能书与战斗共用基础曲线和一次向下取整。战斗中场景无法看到实时状态，将完整标志置为假，客户端改读本人战斗快照。缺行或来源不全时不报完整值。权威退役清单中的已删除技能贡献已知为零；其他未知正重继续标记不完整。

## 一致性与验证

宝宝的未知条目仍占预算，预览不修改存档，保存的整份目标和请求回执一起持久化。五阶身份只在缺值时由种类补齐，转移保留独立实例字段。技能请求使用预期重数和余额重核，阻止重播扣款以及战斗、交接冻结期写入。跨 actor 只传不可变快照。

执行顺序为双来源契约同步及检查、场景与引擎代码变更、全量 clean install，再核对技能书 RPC、所属宝宝、重登、21 个条目方向、五阶身份、装备来源及人物中立预览。正式表源和地图校验保存在契约清单；本轮运行结果另记 PARITY。测试以场景存盘和协议应答验证，Unity 连接的服务版本由该环境的运行证据另行确认。
