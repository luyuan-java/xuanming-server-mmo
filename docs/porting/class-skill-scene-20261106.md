# 职业技能场景生产链

2026-11-06，Java 21。只读来源为 `993b6da9d4ea51d5e4a27cc6ec17004af0fb97c1` 的 `player_skill.cpp` 与 `player_attribute.cpp`；复核至 `9aaedde23`，后续改动是 C++ ECS 缺职业/等级组件拒绝，不照搬到构造即拥有完整输入的 Java 领域对象。C++、同步客户端契约和正式表均未修改。

## 实现

- Java 自有 `PlayerState.skills = 11` 保存 `PlayerSkillBookState` / `PlayerSkillEntry`。`PlayerSkills` 随玩家聚合加载和保存，币与重数共用现有整份 BLOB、事务、owner_epoch 围栏，没有第二份持久真相。未知字段、未知技能、超版本重数和零重保留；仅零技能号和重复号规整，重复号保留首条。
- `ClassSkillCatalog` 是不可变配置快照，用标准集合表达表视图；实际加载从当前职业的 `Class.skill` 发种子，职业/等级不合不发，零重条目原地补一重并保留未知字段。旧通用技能在已拥有职业技能目录的职业不生效，仍保留存档。已学存储重数与受等级、职业及表上限约束的生效重数各自明确。
- `ClassSkillService` 组装 77 完整目录和可用条目；317 修习按次数→技能表→职业→忙碌→expected_rank→逐重计划→扣款处理。一次或十次修习，部分成功只扣实际费用，各正常出口均回完整状态；过期 expected_rank 不重复扣款。
- 扣款复用 `CurrencyService.PreparedDeduction`：先建立完整技能候选，复核旧余额及原技能书，同一逻辑回调先提交两份状态再记审计。审计抛异常不允许只扣钱未加重数。新增 Java 自有审计原因 `TX_SKILL_UPGRADE = 1006`，关联号取技能号。
- `ClassSkillFeature` 声明 GATED freeze/battle 策略，由用例返回业务拒绝和技能书；被动成功变更重算并推属性面板。Java 在选目标阶段也拒绝修习（switchPhase 非 NONE），与已有交接保存时序保持保守互斥。
- 六项被动比例在职业/自然成长/加点/装备加法项之后、向下取整之前应用；暴击百分点加入物理和法术暴击，重复重算从原始输入开始。技能变更按已有属性规则保持当前血蓝比例。治疗加成仍仅由回合引擎消费。
- 战斗快照复制实际有效 rank map，被动进 map 但不进主动列表；未知、异职业、未学或未解锁不出快照。同 epoch 重进场的技能来自原完整内存状态，最终保存后另一节点从同一持久聚合恢复。

## 验证边界

新增 `ClassSkillSceneTest` 11 个方法和 `ClassSkillClientTest` 4 个方法，包含三层未知字段真实业务往返、种子幂等、重数保留、生效夹限、重复扣款、十次部分成功、审计异常、被动重算与血蓝比例、77/317 分发、同代重进场及最终保存到下一节点。现有 `ConfigSceneTablesTest` 保留全表集合断言并增加按职业断言；全功能战斗矩阵登记 317 的参数优先拒绝，真实职业的战斗与交接拒绝由新客户端用例覆盖。

本文件完成时尚未运行编译或测试，执行证据由根任务统一记录。持久字段台账的初代及新增字段版本由根任务独立导出与接入。本项没有新增第三方依赖，不是 C++ 整个实时伤害/Buff 框架的移植，也不是数据库、客户端、多节点实环境验收完成。仍沿用现有周期/最终保存耐久性：应答不是每次修习独立 SQL 提交确认，宕机窗口与其他在线状态一致。
