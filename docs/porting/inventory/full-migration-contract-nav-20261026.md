### 4.2 查询与加载的真实边界

- 固定源 `spatial/system/nav_query.cpp`：内部导航坐标 `(server.y,server.z,server.x)`；最近点搜索半范围 `(2,4,2)`；射线最多 256 个途经多边形；阻挡处回缩 0.05 m；无阻挡还会重新吸附终点取得高度。起点吸附失败时 `ValidateMove` 不修改输出，调用方必须明确兜底。
- 移动 handler 在起点非法时先尝试吸附上报点，再退本场景出生点；帧外推预置当前位置，失败清速度并发 133。Java 当前位图的非法起点直接退出生，进场仅接受位图可走格，并不做 ±2 m 最近点吸附。这些差别需明确保留或按新的后端分别定义，不能称逐位一致。
- `FindPath` 调用 `findPath` / `findStraightPath`，接受 `DT_PARTIAL_RESULT`；header 的“不可达返回 false”不能覆盖实现对部分路径的处理。Java API 宜用完整/部分/失败的明确结果表达，不把部分路径冒充到达终点。
- `navigation.cpp` 同文件只加载一次，每个场景单独探针；失败文件也缓存失败。本源加载失败或出生点探针失败后跳过注册，查询方因没有导航而放行移动。它的日志里“fail-closed”仅指不注册空网格，不能解读为整个 scene 拒启。
- `recast.cpp` 对魔数/版本/部分读取有检查，但零 tileRef/dataSize、分配失败会 break，`addTile` 状态未检查。Java 新读取器应显式校验长度、数量、引用、有限坐标、内存预算、EOF 与 tile 注册结果；不移植这些失效开放行为。
- 注释称 raycast buffer 溢出应保守阻挡，源码实际只检查 `dtStatusFailed(status)`。是否 detail 位能伴随 success，需以固定 ue5navmesh 状态定义及金样确认；不要按注释宣布已覆盖溢出。

### 4.3 生成侧已有能力

`tools/navmesh_baker/navmesh_baker.cpp` 的 mask 路径从 150×150 / 2 m 位图生成地面几何，默认半径 0、体素水平 0.25 m、高度 0.2 m、身高 1.8 m、跨高 0.35 m、坡度 50°、tile 128 体素；OBJ 路径保留其三维输入及悬崖过滤。产物由同套头文件的 ABI 写出 MSET v1。

`sync_current_maps.py` 校验来源合同、布局/导航/mask SHA、位数/尾位/可走格数、出生点，三图全部烘焙与探针成功后才替换，复用文件的 BaseScene 行同步出生点；再经正式导表器产出 PB/manifest，`--verify` 复烘焙比对。Java `ContractSync` 是消费这些权威结果，不具备该生成管线。

完整移植要把“Java 能生成与验证地图资产”另列工具交付。默认不以执行原 C++ 二进制/JNI 作为 Java 实现，也不为此新增依赖。先做现有冻结产物的消费与验证，再拆分 mask 输入、OBJ 输入、三角网/导航数据生成与验证；生成输出只进入 Java 工具指定目录，权威共享合同仍走正规同步，不改 C++ 表或配置。若暂不实施通用烘焙算法，必须继续标 Java 待做。
