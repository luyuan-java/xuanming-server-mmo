## 已接入引擎的行为

- 开局按角色职业、等级、解锁等级和表上限复核 `skill_ranks`，保留有效被动重数；技能 ID 列表不能凭空授予职业技能重数，未学主动技能被剔除。请求本身不被修改。
- 提交和出手共用校验链。职业技能区分敌方、友方和自身；已死/逃离的同阵营主目标允许出手时补位，错阵营仍拒绝。费用取最大法力比例，职业技能只看本技能冷却，与通用共享组隔离。
- 目标选择不消费随机数：主目标优先；治疗再按气血比例，随后按阵位和 actor ID 无符号升序；包含同阵营宝宝，零上限按一个目标。
- 没有目标时不扣费、不创建冷却、不发事件。成功时先 SKILL、一次 MANA 扣费，再按目标发伤害、治疗、回蓝、驱散、buff；逐目标标记 hit_index 并在结束时恢复零。出手复核失败，敌方技能回退普攻，友方/自身技能作废。
- 伤害使用有效物攻/防御和重数系数；治疗使用法伤、等级、治疗被动及残血阈值；回蓝按扣费后的实际缺口夹限。致死后不继续挂效果。
- 职业技能 initiative 仅在完整校验通过时影响本回合出手顺序，再按有效速度、无符号 ID 排序。普攻、通用技能、逃跑速度差已接入局内有效属性。
- 自动玩家在没有手动待执行动作时调用独立选择器；非挂机超时、宝宝和怪物保留各自默认动作。选择器实现和评分依据见 [挂机选技](class-skill-auto-20261106.md)。

## 数值和历史行为边界

职业治疗跟随固定源的新 `LandedHeal`：先取非负缺口，再按实际回复量截断；使用 unsigned long 比较与饱和转换，不把当前 uint64 气血先转 double。超过最大血量时回复零，不制造回绕；高于 2^53 的已有气血保留低位。选择器与实际职业治疗共用这一函数。

旧通用/周期治疗仍沿用 `BattleUnit.applyHeal` 的历史行为；它与固定源已更新的全局治疗原语存在差异，需要独立调整现有回归期望后统一。本批没有删改旧断言，也没有把这个缺口标为完成。

新职业 MANA 事件填写 optional `mana_delta`，`value` 始终保留精确 uint64 实际量。超过 signed 64 可表达范围时，显示增量饱和为 Long.MAX_VALUE/Long.MIN_VALUE，避免回复被显示成扣除；这是 Java 明确的有意差异，不复制 C++ 越范围有符号转换的结果。旧通用技能扣蓝暂保留原事件字节，没有新增 delta，仍记为待统一项。

技能表 `cooldown_rounds + 1` 采用协议 uint32 回绕口径；正常表值表示本回合末先衰减，随后完整等待配置回合数。全部纯查询不改变 RNG，真实暴击仍按原规则消耗随机数（100% 也抽一次）。
