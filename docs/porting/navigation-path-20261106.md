## API 与失败语义

```java
NavMeshPathQuery paths = new NavMeshPathQuery(mesh);
var result = paths.findPath(startReference, startPoint, endReference, endPoint,
        NavMeshQuery.Filter.walkable());
if (result.status() == NavMeshPathQuery.Status.COMPLETE) {
    // corridor 是完整 ground 引用序列；points 包含各段的地表高度与所属面。
    consume(result.points());
}
```

输入直接使用导航 Y-up 米制坐标。起终引用必须属于该 mesh 且通过 filter，XZ 位于指定凸面；Y 从其细节面投影。显式引用选定层，不按传入 Y 改选另一层，不自动吸附到其他多边形。坐标必须有限且绝对值不超过 1e9，与前段查询合同一致。

| 状态 | 含义 |
|---|---|
| `COMPLETE` | 已找到完整走廊，且输出点列全部通过地表与跨门验证 |
| `INVALID_START` / `INVALID_END` | 指定引用、过滤或水平位置非法，或端点没有细节面高度 |
| `UNREACHABLE` | 搜索完成但指定终面不可达，或所选走廊无法证明为可用地表点列 |
| `LIMIT_REACHED` | 工作量、搜索面或点列预算不足，不能据此断言目标不可达 |

除 `COMPLETE` 外，结果的走廊和点列都为空。所有返回列表均不可修改。原地查询返回一个投影点；同面查询也补充细节地形的高度折点。

## 搜索与地表拉直

`NavMeshPathQuery` 复用 `NavMeshQuery` 的不可变面和门户索引。内部邻接来自读取层验证过的互反边，跨 tile 邻接只接受相邻格、反向门户、同平面及真实正长度重叠。serialized runtime links 不参与查询。

1. 在每条门户上按两侧 detail 三角形切片，逐段解线性高度差不超过 `walkableClimb` 的区间。不能因为整条边的中点过高就丢弃其余可走部分，也不能把中点可走当作全边可走。
2. 每个地表面的固定锚点为凸面顶点均值的地表投影，起终面使用实际输入端点。边权为锚点经合法门户中点到下一锚点的三维折线距离。A* 使用三维直线距离作为下界；代价相同按无符号引用稳定选择，不受 tile 输入顺序影响。这里的最优是固定锚点图上的最优，不承诺连续空间最短路。
3. 找到走廊后，优先尝试直达终点，再尝试最远可见的后续门户中点。每条候选线只能按已选走廊顺序穿过合法门户，不能跳过墙或切到另一层。无法拉直时沿门户中点前进；不采用可能落在开放门户端点上的未经验证角点。
4. 每个面内段按 detail 三角形边界补高度折点，以地表高度生成点列。跨门保留出发面与到达面两个点，即使 XZ 相同；存在台阶时保留双方 Y，差值必须满足 climb。调用方不能不看引用和高度就把这些点合并为穿地直线。

门户两端收缩 2e-8 米，仅排除数值角点接触，不代表角色半径或避障余量。外部射线原有 1e-8 米开放边界保持不变；路径采用更保守的端点选择，角点结果不承诺与原生压缩门户一致。直线恰好沿门户共线时可能采用中点折线绕过歧义，不据此穿越未证明的邻接。

索引创建后不变；A* 优先队列、最佳节点、父节点、锚点缓存、门户高度区间、拉直点列和预算均为单次调用私有，不借用全局场景状态。默认上限为 1,048,576 工作单元、4,096 搜索面和 16,384 点，硬上限分别为 16,777,216、65,536 和 262,144。扫描细节三角形、邻接候选、队列项、回溯和拉直尝试均计入工作预算；不能证明完整结果时保守失败。尚未做性能或容量验收。

## 场景接入只读复核

当前 `game-scene` 仍由 `SceneNodeConfiguration` 启动读取 `ConfigSceneTables`，后者仅对 `main/penglai/donghai` 映射为 `CurrentMapNavigation` 的三图 mask。`SceneNavigation` 接口只有 `isWalkable`、`trace` 和 `velocity`，没有路径查询；`game-scene` 也未依赖 `game-navigation`。进场、移动上报和外推继续调用既有策略，没有因为新增查询类自动使用 MSET。

后续生产接入需明确：启动时读取并核验 MSET 的来源与失败策略；服务器 `(x,y,z)` 和导航 `(y,z,x)` 的边界转换；进场吸附、移动阻挡回缩和多层终点归属；按场景配置选择导航策略；路径业务调用方、预算失败和不可达响应；原三图 mask 行为与旧无导航场景回归。文件 I/O 应在启动/重载阶段完成，运行中的场景逻辑线程只查询不可变数据。不能在该批测试未跑、剩余地图未同步核验时将三图策略直接替换并标为完整对齐。
