## 接口与职责

包内类 `AutoClassSkillSelector(BattleContext, ActionChecks, ClassSkillExecution, BuffEngine)` 用构造器接收本局对象，`select(BattleUnit)` 返回 `Optional<BattleAction>`。空值表示继续默认普攻。调用方只对没有手动待执行动作的 `is_auto` 玩家调用；非挂机玩家超时、宝宝和怪物沿用既有默认动作逻辑。

候选用不可变 `Candidate` record 表达；用途使用封闭 enum。局部变量保存本次最优项，不引入全局状态、框架、I/O 或第三方库。选择只读取当前状态，不消费 RNG、不追加事件、不扣蓝、不挂 buff、不预占冷却。行动里只给技能和目标，出手时仍由正式执行器复验。

共用判据与计算：

- `ActionChecks.checkActionPrerequisites` 排除不可施放、未学、错职业、非法阵营、冷却、沉默、法力不足及失效单位。
- `ClassSkillExecution.selectTargets` 提供同一目标集合及顺序；`landedHeal` 与实际职业技能治疗共用缺口封顶和整数截断，避免先加大整数再转 double 造成收益偏差。
- `BattleContext.expectedDamage` 共用护甲、有效防御、对应类型抗性、PVP 比例与暴击期望；落血使用 `CombatDamageRules.damageToHealth`，防御减半、向上取整、剩余血量封顶。
- `BuffEngine.isDebuffEntry` / `isImmuneToBuff` 放为包内只读方法，选择和实际驱散/挂 buff 使用相同规则；不另复制一套标签判断。
- `ClassSkillCombat.statMultiplier` 比较挂前与挂后的最强正向、最强负向组合；`EquipmentCombatRules.addSaturated` 累计 uint64 收益。

## 固定源行为

主函数及帮助函数来源为 `turn_battle_engine.cpp:1687–1927`，候选全序在 `:133–172`，治疗/回蓝比例在 `:93–115`，预测落血/治疗在 `:2387–2425`；阈值来自 `turn_battle_constants.h:120–123`。

| 用途优先级 | 入选和收益 |
|---|---|
| 1 危急治疗 | 非敌对技能，自动目标集最缺血者低于 30%；收益为各目标实际缺口内可恢复的整数气血之和。行动 target=0，出手时重排。 |
| 2 驱散 | 非敌对技能；每目标取 min(dispel_count,可驱散条目数)，首目标必须真有减益；行动明确指定首目标，避免混合治疗技能落错人。 |
| 3 常规治疗 | 与危急治疗相同的收益；最缺血者不高于 70%，且未低于 30%。 |
| 4 回蓝 | 目标中至少一人当前法力不高于 30%；实际恢复总量减本次耗蓝后必须严格大于零。算施法者缺口时先扣本次耗蓝；零蓝条按满蓝。 |
| 5 属性增减益 | 友方只取正幅度，敌方只取负幅度；物攻、防御、速度以实际属性点变化计收益。防御增益要求目标血量不高于 60%；速度变化须翻转与至少一个存活敌人的出手先后，同速按无符号 actor_id。免疫或未知 buff 类型无收益。 |
| 6 伤害 | 各目标预计实扣之和必须严格大于普攻基线。普攻基线为各存活敌人上的预计伤害平均值，并包含逐段连击概率及追加段折扣。 |

同用途按收益降序、耗蓝升序、冷却回合升序、技能 ID 升序、目标 ID 升序决胜，所有协议整数按 uint32/uint64 比较。技能列表和目标容器遍历次序不影响同分选择。治疗量、回蓝量、属性点和伤害的单位不同，不跨用途比较分数。

源 `ExpectedDamage` 没有额外乘命中概率：当前正式命中率固定 100%，选招与出手一致；未来命中/闪避若变动，必须同批补预测口径。属性 buff 预估也保留源“逐 effect 读取当前状态”的行为，不模拟在同一候选里先挂前一个 effect 后挂下一个。它是固定源启发式选择，不承诺搜索未来回合或最优战术。

旧通用/周期 `BattleUnit.applyHeal` 的历史 double 相加行为本批未统一；本次职业执行和挂机预测共用新缺口原语。scene 的六项派生属性和暴击被动应在快照生成前计算，选择器不能再次补乘；只有 outgoingHeal 在引擎按技能重数现算。
