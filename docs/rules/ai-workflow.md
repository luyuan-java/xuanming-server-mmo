# AI 协作约定与模型档位规定（Java 版）

> 对应根索引 [AGENTS.md](../../AGENTS.md)。新电脑或新 AI Agent 启动前请先完成必装 Skills 安装 → [required-skills.md](required-skills.md)。

## 1. 分工与构建测试权限

- **本仓库构建测试权限**：Claude 在本仓库**可以自行编译和跑测试**（用户 2026-09-29 授权，仅限本仓库；C++/Go 权威仓仍按其 §10.1 执行）。
- **协同分工**：当某会话只负责业务代码实现时，契约同步、全量构建与冒烟验证也可交由 Gemini 执行（交接时写清目标模块、命令、工作目录、通过标准与需保留日志）；**Codex 仅负责作图（UI / 美术素材 / 视觉精修）**，不参与编码、分析、编译、协议生成、测试、压测与运维收尾。
- **严禁无运行证据宣称通过**：未执行的候选和历史失败证据不能记为验证通过；没有实际运行输出时不得声称“编译通过”或“测试通过”。

## 2. 执行与安全写回

- 先过会话启动门禁并检查工作区既有改动，不覆盖、回退或顺手格式化他人的在途代码。
- 涉及双版本功能时，完成即在根目录 `PARITY.md` 登记并在交付说明中写明 C++/Go 版状态。
- 失败时不假装成功、不连续自动重试、不删断言或跳过测试，保留首错原文与日志路径并报告。

## 3. 模型档位规定（强制，负责人 2026-11-20 定，2026-11-21 补充，2026-11-25 修订）

- **写/修改代码，以及需求分析、设计分析、思想分析、漏洞分析、步骤分析、执行步骤，必须使用各软件当时的最高档模型**，不得在低档模型上执行：
  - Claude Code：`Fable 5.2 Max`
  - Gemini：`Gemini 4 Neon Extra`
- **仅编译、同步契约、跑测试与冒烟使用低档模型**（遇到需要改代码或需做上述分析/步骤设计的报错先保留首错原文停下，切回最高档模型再处理）：
  - Gemini：`Carbon Medium`
  - Claude Code：`Opus 5 High`
- **Codex 职责限定**：Codex 仅负责作图（UI / 美术素材 / 视觉精修），不参与编码、分析、编译、协议生成、测试、压测与运维收尾。

## 4. 设计方案强制落盘 `.md` 与异机作图交接（强制，负责人 2026-11-21 定，2026-11-25 补充）

- 以后凡是编写策划或技术设计方案，**Claude Code（及其他 AI Agent）在写好设计之后，必须将完整的分析与方案保存到 `.md` 文件中**，不得只停留在对话回复里：
  - 必须落盘的内容涵盖：**需求分析、设计分析、思想分析、漏洞分析、步骤分析、执行步骤**以及最终设计方案。
  - 保存位置：写入 `docs/design/<主题>.md`（或更新对应的既有设计文档）。
- **玩法闭环、不硬扩展与异机 Codex 作图交接铁律**：玩法接入完毕须确认逻辑、服务端/客户端代码与 UI 接入全部闭环，确实还能扩展得更好玩才继续扩展（**不要硬扩展，没可玩性不要扩展**）；需要让 Codex 做新 UI 时必须告知负责人，且因**另一台电脑上的 Codex 拿不到任何本地文件**，写完 `.md` 后**严禁只给 `.md` 路径**，必须在回复中直接输出可直接整段复制给 Codex 的**纯功能作图信息**——**只告诉 Codex 做什么 UI，不要告诉 GPT / Codex 要定什么风格**（严禁写任何画风、风格词、材质词或色号/配色，禁止抄旧文档或旧代码的配色词），且**输出目录一律新建在图仓 `D:\work\image\designs\<新专题目录>\` 并严禁与 Unity / 游戏代码有任何关系**（禁写 `Unity`、`uGUI`、`Prefab`、`Canvas`、`Sprite`、`spriteBorder`、`.meta`、`mmorpg-client`、`Assets/Resources/`、C# 脚本名或协议/RPC 名；留档 `.md` 若需记本机导入路径须单放文末「本机研发导入备忘」，严禁混进复制给 Codex 的正文；只写要做什么 UI、用途、尺寸、文件名、透明底 PNG-32、文字留空规则、拉伸留白与图仓输出目录）。
